# MerchantPay V0.6.3.1 — Invoice Creation Fix

Root cause found from testing V0.6.3:

- The Products & Services screen uses Prisma `Item`.
- The invoice POST route was incorrectly checking `db.product`.
- The Prisma schema contains both legacy `Product` and current `Item` models.
- Therefore selecting an item from the current UI caused the API to return HTTP 404: "Selected product/service not found."

Fix:
- Invoice creation now validates the selected catalog entry against `db.item` and the current merchant/business.
- The invoice stores the selected item's name and price as a historical invoice snapshot.
- It does not incorrectly place an `Item` id into `InvoiceItem.productId`, because that foreign key belongs to the legacy `Product` model.
- No database migration is required for this fix.

Navigation and all other V0.6.3 stability changes are retained.
